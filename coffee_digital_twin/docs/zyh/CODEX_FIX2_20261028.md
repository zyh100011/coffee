## G6 降雨接入 HYDRUS（张源皓授权按数据判断口径）

**数据核查结论**（2026-10-28 对冻结库 data-v1.0 逐日核对）：

- 环境监测点 1/2/3 的 `rainfall_raw` 是日累计计数器：每天 00:00 左右归零，之后单调累加，当天最大值就是当日雨量。例如环境监测点1 在 2026-06-11 从 02:17 的 0 逐步升到 21.8mm。
- 有两类干扰：
  - 当天第一条记录可能是前一天的残留值，例如 06-13 00:00 读数 7.0，之后才归零；
  - 白天偶尔出现单点 0，下一条又恢复原累计值，例如 06-11 13:34。
- 三个环境监测点的日雨量基本一致，只有 06-10 差异较大（25.0 / 45.6 / 27.6mm）。
- 基地气象站（原 7a59d3a9）规律不同，一天内多次升降，且只有 2025 年数据，**不用于模型**，农情页照常显示。

**计算口径**：新增 `services/rainfall.py::daily_rainfall(plot_id, source, start, end)`，按需从冻结观测计算，不改 obs 原值。

1. 只取 `parameter='rainfall_raw'`、`unit='mm'`、`qc_flag='ok'` 的记录。来源默认“环境监测点1”，与默认的土壤监测点1 对应。
2. 每天先找第一条 ≤0.05 的记录，视为当日归零点，归零点之前的读数丢弃。
3. 日雨量 = 归零点之后所有读数的最大值。白天的单点 0 不影响最大值，不需要另外处理。
4. 当天没有归零点时：只有一条记录或全为 0，记 0；有多条大于 0 的读数，取当天最大值，并记一条 warning。
5. 当天没有记录：记 `null`，HYDRUS 按 0 计算，并在 assumptions 里写“X 日无降雨记录，按 0 计”。

**接入**：

- `hydrus_adapter._build_hydrus_input` 的实测降雨改为调用 `daily_rainfall`，第 i 天降水 = 当日雨量 + 当日灌溉（换算成 cm）。只改外层包装，不改求解。
- 回读核验：06-09～06-15 环境监测点1 按上述规则应得 2.8、25.0、21.8、7.0、0.2、1.4、0.8mm，合计 59.0mm。写成测试，与 ATMOSPH.IN 回读的 `daily_prec_cm` 比对，误差小于 0.001cm。
- 情景对比的参数核验规则不变：两组降雨相同，第 1 天差值仍须等于 change/10。
- `real_data_profile.json`：`rainfall_counter_review.model_daily_rain_enabled` 改为 true，写明上述口径；从 `missing_fields` 删除 `rainfall_accumulation_mode`。
- 农情页：降雨参数在用户模式下显示为“日降雨量（mm）”，按同一规则逐日给出；原始累计读数只在开发者模式显示。
- 运行 `tools/verify_scenario_live.py`，跑新窗口（06-09 起，0 vs 20mm）。
  - 通过：保持 live。
  - HYDRUS 不收敛或失败：写入 PROGRESS，情景页这一窗口改用回放；降雨接入代码和测试保留，不要退回 0 降雨。
