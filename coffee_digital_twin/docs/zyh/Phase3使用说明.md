# Phase 3 使用与验收说明

工程已在原生微信小程序上增量改造，沿用原配色与框架，没有引入 npm/UI 库或 ECharts。四个 tab 为工作台、问答、农情、情景。Phase 3 已实现公共组件、地块与农事、循证问答、农情查询、模型结果、报告与证据详情。情景 A/B 三步向导和 compare 接口按计划属于 Phase 4，当前入口说明了这一边界。

## 启动与刷新

1. 关闭旧后端启动窗口中的服务（Ctrl+C），再在工程根目录运行 `./server/start_backend.ps1`。默认监听 `127.0.0.1:5000`；不要同时启动两个同端口后端。
2. 开发期需本地 mock 时，另开 PowerShell，在 backend 目录执行 `../.venv/Scripts/python.exe tools/mock_evidence_service.py --port 8001`。mock 服务只监听本机，页面明确展示 MOCK。真实服务地址确认后通过 EVIDENCE_SERVICE_URL 配置。
3. 微信开发者工具导入 `E:/coffe model/coffee_competition_zyh/coffee_digital_twin/miniprogram`，点击“编译”刷新。当前三个本地项目/地址配置保留，未混入任务提交。
4. 首次进入工作台，选择或新建地块。新表单不预填示例参数；为有依据的字段选择“现场记录”。农事的日期、数量、单位都需填写。

## 页面路径

| 页面 | 当前行为 | 缺资料时 |
|---|---|---|
| 工作台 | 当前地块、完整度、已有40cm数据与模型状态、问答快捷入口 | 空态与缺项，不生成观测 |
| 问答 | 消息块、一次追问、来源、证据、报告入口；10轮历史 | mock明确标记，服务不可用时保留可用事实 |
| 农情 | catalog决定参数/深度/时间，可查日均或原始值、原行出处 | 空态；字段映射确认后才入库 |
| 地块/农事 | 12字段与来源、数量/单位/日期校验 | 未填字段保持空 |
| 结果 | 模型状态与来源标签，HYDRUS剖面和三深度序列 | 失败工具不进入解释依据 |
| 证据 | 实际输入、假设、版本、warnings、引用/原始行回查 | 不存在的证据显示错误 |
| 报告 | 固定五节，证据绑定，浏览器HTML打印链接 | 无证据明确提示；没有自动凑齐三模型 |
