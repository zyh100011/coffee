# 答辩问题准备

## 为什么采用微信小程序？

果农使用成本低，免安装，适合田间地头快速录入农事数据。

## 为什么用 Flask？

MVP 阶段接口少、部署轻，Flask 便于快速把小程序请求、SQLite 和模型 adapter 串起来。

## 三模型如何协同？

APSIM 负责生育期、产量和水肥胁迫，HYDRUS 解释土壤水分和根系吸水，BEPS 扩展冠层生产力和生态指标，后端统一融合为小程序可展示的 JSON。

## 演示时模型不可用怎么办？

adapter 保留标准 JSON 兜底输出，确保演示流程不断链。


## 本届业务与 HYDRUS（2026-10-28）

以下是当前实际实现，优先于上方旧MVP历史说明。

1. **为什么称为假设情景？** HYDRUS模板的土壤水力参数和初始剖面没有完成本基地现场标定；已有监测和土壤化学报告不能证明水力参数已校准。`models/hydrus_adapter.py`保留simulation_uncalibrated来源、assumptions和missing_fields；输出解释固定假设下的水分响应，不宣称预测精度或直接灌溉处方。
2. **怎样证明参数确实进了模型？** `services/scenario_service.py`核对两次运行的实际输入反读值。20mm额外灌溉要求首日daily_prec_cm差2cm、其余日差0，蒸发/蒸腾、地块、模型/参数版本和窗口相同。核验失败不展示差值。FIX06_历史窗口核验.json记录了真实Windows引擎0/20mm的隔离核验；不是田间实测验证。
3. **fallback怎样区分？** 统一契约只允许success/replay的有效非demo结果进入解释，fallback显示演示身份；失败/超时/缺条件不冒充成功。replay读取已有案例并保留原日期、地块和参数。真实服务不可达时只保留数据事实和不可用说明，mock始终标明规则联调，不是正式模型。
4. **真实数据怎样去重和回查？** `ingest_project_raw.py`保留字符串设备号、来源文件哈希、原值、行号、质量标记和设备时间参数组合的去重逻辑；冲突不覆盖成猜测值。`data_service.py`按地块/参数/层/设备/单位/版本查询。证据详情分页返回原始记录与SHA256；data_release_sources保留data-v1.0之前的逐文件导入版本。20条案例提供参数化SQL复现，均值独立核对误差0。异常保留，日累计原雨量不直接求和冒充日降雨量。
5. **无鉴权服务的安全边界？** 目前Flask业务接口无用户鉴权，默认脚本绑定127.0.0.1；手机演示只在可信局域网显式绑定0.0.0.0，结束后关闭。蔡服务的Bearer令牌只保存在后端.env，不等于Flask用户鉴权。白名单和参数schema限制工具，模型生成文本不进入shell或文件路径执行；不使用公网隧道。
